# STEP7_REPORT: экспорт экрана и мастера (STUDIO_PLAN8, Шаг 7)

## Что сделано
Кнопка «Экспорт» (шапка, на планшете и шире) и пункт меню проекта «Экспорт экрана (пакет для ИИ-кодера)» открывают окно. Экспортируется выбранный экран или мастер. Режим (app / module / skin) берётся из профиля экрана.

В окне: поле префикса модуля, поле дополнительных селекторов (только module), «Собрать экспорт», статус самопроверки, блоки с отдельными кнопками «Скопировать» (пакет .md, CSS, токены, разметка, строки ru/en, действия data-a, файлы и шрифты, кнопки оценки, JSON), «Скачать .md», «Скачать .json», отчёт с предупреждениями.

Как устроено:
- CSS экспорта строится той же функцией `ST.nodes.css`, что и холст, поэтому они не расходятся.
- Классы называются `{prefix}-{экран}-{элемент}`. Занятые приложением имена пропускаются (списки для `sj` взяты из приложенных sj-файлов).
- Переменные студии заменяются на переменные приложения, градиенты раскрываются, запрещённое по §8 контракта проверяется (`<nav>`, `width:390px`, z-index 6–8, глобальные селекторы, `font:` с inherit).
- Разметка: функция `{NS}.{camel}Html(d)` возвращает строку, `esc()` и `T()` как в приложении. Кнопки выводятся как `<button type="button" data-a>`.
- Самопроверка: экспорт подставляется в изолированный iframe и сравнивается с холстом по положению и размеру (допуск 1 px) и по виду, в светлой и тёмной теме. В module дополнительно проверяется утечка стиля. При ошибках или расхождениях копирование заблокировано (кнопка «Всё равно показать код» с подтверждением).
- Режим skin: блоки `:root[data-skin=…]` и шаги приложения S1–S3, самопроверка не применяется.
- Проект экспортом не меняется: записи в историю нет, iframe удаляется.

## Проверить руками на планшете
1. Нажать «Экспорт» на экране с узлами: статус должен стать зелёным «✓ Самопроверка».
2. «Скопировать» у блока CSS, вставить в заметки: текст должен начинаться с `.sj-…{`.
3. «Скачать .md»: файл появляется в «Загрузках», в нём 12 разделов.
4. Переключить профиль экрана на module и skin, собрать заново, сравнить блоки.
5. На телефоне кнопки в шапке нет, экспорт открывается через меню проекта.

## Риски
- Самопроверка использует упрощённые глобальные `.card`, `.btn`, `.chip`, `.row` (файлов приложения в студии нет). Разницу с настоящим styles.css она не увидит.
- Списки занятых имён известны только для `sj`. Для других префиксов в отчёте написано проверить имена поиском по проекту.
- Шрифты в проверочном окне могут не успеть загрузиться: тогда расхождения текста считаются «слабыми», и проверка не блокирует копирование (с пометкой в окне).
- Реальный буфер на iOS работает по нажатию пользователя; если браузер откажет, остаётся «Показать» и выделение вручную.

## Замечено, но не тронуто
- Старые страницы `st-test.html`, `st-test-tokens.html`, `st-test-fonts.html`, `st-test-nodes.html` падают с `Cannot read properties of undefined (reading 'seed')` и на нетронутом архиве, не из-за Шага 7. `st-test-comp.js` и `st-test-profiles.js` не подключены ни к одной html-странице.
- Пустые рамки без размера показываются на холсте высотой 24 px, в экспорте они получают предупреждение.
- Английские строки пока равны русским.
- Нет обязательного компонента нижней панели: экспорт её просто не включает.
- При добавлении на экран узла шириной 390 страница на телефоне шире на 10 px (холст `.st-stage`). От экспорта это не зависит.
